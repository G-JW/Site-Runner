# Site Runner：功能清单与界面设计

核对日期：2026-10-15。当前源码版本 0.3.6，功能依据本地代码及 Preload API 核对；新版应用在 `release/Site Runner 0.3.5.app`，此前应用包保留。

## 1. 产品定位与完整功能地图

Site Runner 是本地优先的桌面浏览器自动化工具：保存网站任务及登录环境，用 Playwright 执行网页操作，记录结果，并按配置发送批量汇总通知。技术结构是 Electron + React + TypeScript + SQLite + Playwright / Chromium。

| ------------ | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------- |
| 任务         | 新建、编辑、删除、启用、停用                         | 每个任务保存名称、HTTP/HTTPS URL、操作脚本、登录环境、超时、分组、计划、访问选项、创建/修改时间及最近结果                                  | 左侧「任务」；创建按钮；命令面板 |
| 今天         | 成功、需要处理、今天尚未运行                         | 每个任务仅统计今天最后一次结果；点击摘要筛选；尚未运行只统计启用任务                                                                       | 任务页顶部三项摘要               |
| 查找         | 搜索名称/URL、状态筛选、排序                         | 限定当前分组；筛选全部、启用、停用、成功、失败、尚未运行、执行/等待、今日结果；默认顺序、名称或最近运行排序                                | 列表工具栏                       |

| 模板双语     | 名称、简介、说明分别存中英文                         | 按当前语言编辑；新模板最初两种语言使用相同文字；允许保留空模板库                                                                           | 模板编辑器                       |

| Webhook      | URL、POST/PUT/PATCH、自定义请求头                    | 请求头键值表单；发送完整 NotificationMessage JSON                                                                                          | 通知渠道表单                     |
| 通知路由     | 批量/定时通知开关、匹配检查                          | 分别显示全部成功、有失败时匹配的启用渠道；无匹配说明原因；保存/删除/刷新重新核对                                                           | 左侧「通知」                     |

| 汇总内容     | 总数、成功、失败、失败网站与简短错误                 | 停止批次另显示实际/计划数；错误最多 180 字符；长诊断与堆栈去除；未自动脱敏                                                                 | 批量与定时结束通知               |

软件更新入口为 **设置 → 软件更新**：检查 GitHub Releases、签名验证、下载进度、一次点击更新并重启；数据沿用原目录，运行中与录制状态阻止安装。发布机制与范围详见 [RELEASING.md](RELEASING.md)。

## 2. 参数、数据及限制

### 2.1 默认与范围

| 配置                  | 默认        | 说明                                                    |
| --------------------- | ----------- | ------------------------------------------------------- |
| 新任务超时            | 30000 ms    | 允许 1000–300000 ms；编辑器以秒显示                     |
| 浏览器无头            | 关闭        | 只影响后续 GUI 自动化；CLI 默认无头，CLI 选项不修改偏好 |
| 批量通知              | 开启        | 还需要匹配且启用的渠道                                  |
| 定时通知              | 关闭        | 还需全局通知开启                                        |
| 语言                  | English     | 可切换简体中文                                          |
| 主题 / 密度           | 系统 / 舒适 | 保存在本地数据库                                        |
| 新任务空脚本停留      | 5000 ms     | 0–60000 ms；默认识别常见验证页                          |
| 历史保留 / 备份保留   | 90 / 30 天  | 自动清理默认关闭                                        |
| 界面实时日志          | 200 条      | 可手动清空，重载不保留                                  |
| 单次持久化日志        | 1000 条     | 每条至多 4000 字符                                      |
| 历史页 / 通知发送记录 | 50 / 100 条 | 前者分页，后者最近记录                                  |

数据存于 Electron userData 下的 site-runner.sqlite3，以及 profiles/、screenshots/、logs/、backups/。实际路径以设置展示或 --user-data / SITE_RUNNER_USER_DATA 为准。

凭据与登录状态仅存本地，数据库里的通知 Token/请求头当前没有额外加密。脚本作为可信本机代码执行，没有恶意脚本安全沙箱。导出不包含登录环境实际数据、渠道密钥和历史，但脚本/URL 中手写的敏感内容不会被自动删除。

空脚本访问的验证页识别是辅助机制，可能误判或漏判；应通过显式文字/元素检查验证签到等业务结果。旧版独立结果检查已停用，旧历史保留。

### 2.2 CLI 操作

- --help；--list-sites；--list-folders。
- --run-all；--run-site <ID 或精确名称>；--run-folder <ID 或精确名称>。重名时使用 ID。
- --headed / --headless；--user-data <绝对路径>；环境变量 SITE_RUNNER_USER_DATA。
- --run-all 与 --run-folder 执行启用任务；显式 --run-site 可执行停用任务。
- JSON 输出；退出码 0 成功、1 执行/通知/启动失败、2 参数或任务无效、3 同一数据目录已有实例。
- CLI 单任务也按批次通知策略发送一次汇总；空批次不通知，通知最多等待 15 秒。
- 需要复用登录状态时由同一系统用户运行；GUI 常驻与同数据目录 CLI 不能同时使用。
- macOS launchd / Windows Task Scheduler 用法见 README 与 examples；Windows 示例尚未在 Windows 环境实测。

## 3. UI 与交互重设计

### 3.1 风格依据

参考 VS Code / Obsidian 的轻量导航、稳定内容区、克制配色和键盘操作习惯。界面围绕配置与运行任务，不引入工作区管理等额外概念。

### 3.2 界面结构（已实现）

```text
┌─ Site Runner ───── 搜索任务或命令 ───── 侧栏 / 输出 ─┐
│ 任务         │ 当前功能的配置与操作                   │
│ 运行记录     │ 页面标题、主要操作                     │
│ 脚本模板     │                                       │
│ 登录环境     │                                       │
│ 通知         │                                       │
│ 数据与备份   │                                       │
│ 设置         │                                       │
│ 系统自动化   │                                       │
│ ──────────── │                                       │
│ 任务分组     │                                       │
│（仅任务页）  ├─ 运行输出 · 筛选 / 跟随 / 清空 ───────┤
│ 运行输出     │ 批次进度、停止后续、实时日志            │
├──────────────┴───────────────────────────────────────┤
│ 就绪 / 执行中                   任务 / 环境数 · 时区 │
└──────────────────────────────────────────────────────┘
```

| 区域       | 交互                                                            | 设计目的                   |
| ---------- | --------------------------------------------------------------- | -------------------------- |
| 左侧功能栏 | 八个功能直接可达；折叠为图标后保留可访问名称与提示              | 配置入口清晰，消除双重导航 |
| 任务分组   | 仅任务页显示全部、未分类及自定义分组；独立滚动                  | 分类辅助任务操作           |
| 主内容区   | 始终显示一个功能；返回任务保留筛选和选择                        | 不需要管理页面标签         |
| 设置       | 页内分类为全部、外观、执行；独立通知与数据入口                  | 减少重复功能组织           |
| 系统自动化 | 平台、路径、范围、时间生成可复制命令；按验证→注册→检查/停用编排 | 明确如何交给电脑自动运行   |
| 命令中心   | 搜索页面、任务名称/URL及常用命令；⌘/Ctrl K                      | 键盘快速操作               |
| 全局输出   | 跨页共用，运行时展开，可过滤与收起                              | 持续反馈执行状态           |
| 布局记忆   | 侧栏折叠和输出开关保存到 localStorage                           | 再次打开保留偏好           |

编辑任务保留五步骤及未保存草稿确认，模板录制期间保留切换页面保护。系统自动化说明仅生成示例，不注册实际系统任务；GUI 与 CLI 共用数据时需先退出应用，Windows 示例尚未在 Windows 系统验证。

### 3.3 任务编辑工作流（已实现）

任务配置覆盖主编辑区，保留左侧资源背景。左侧纵向五步导航，右侧配置正文，底部固定保存/返回/继续操作；表单独立滚动。顶部展示任务名、URL 与未保存标记。

1. **网站**：名称、URL、分组、启用状态；高级超时折叠。
2. **登录**：复用持久化环境打开网站；高级环境选择折叠。
3. **操作**：仅访问、可视化步骤、录制、TypeScript；模板以复制方式应用；更换已有操作确认。
4. **试运行**：可跳过；保存后真实运行一次，显示结果与错误说明；高级访问选项折叠。
5. **计划**：跟随分组、单独计划、仅手动；常见频率表单、自定义 Cron、下次执行和时区。

进入后续步骤先核对名称及 HTTP/HTTPS URL；未保存关闭会提示；录制/保存期间锁定步骤和退出；可视化步骤验证失败回到操作页。此次改动保留原有主进程执行、调度、导入与数据库行为。

### 3.4 视觉规范（已实现）

- 浅色：白色内容区、灰色资源栏、柔和灰紫选中态；深色：近黑灰表面、灰紫强调。
- 强调色用于当前入口、选中页签、主要操作、焦点；成功绿、失败红仍有对应文字。
- 系统无衬线界面；Cron、代码、日志、时间采用等宽字体；界面通常 10–13 px，标题 23 px。
- 单侧栏默认 216 px，小窗口 200 px，折叠为 56 px 的图标栏；支持最低 1040 × 680 窗口。
- 细分隔线、4–5 px 控件圆角、低高度工具栏；表格密度由设置决定。
- 长 URL 与日志支持截断/换行；表格必要时区域内横向滚动，不挤出主工作区。
- 深浅主题、紧凑/舒适、中英文沿用统一配置；减少动态效果的系统偏好继续有效。

### 3.5 键盘与可访问性（已实现）

| 操作            | 快捷键                                  |
| --------------- | --------------------------------------- |
| 搜索任务/命令   | ⌘K / Ctrl K，或 ⌘Shift P / Ctrl Shift P |
| 设置            | ⌘, / Ctrl ,                             |
| 展开/收起功能栏 | ⌘B / Ctrl B                             |
| 展开/收起输出   | ⌘J / Ctrl J                             |
